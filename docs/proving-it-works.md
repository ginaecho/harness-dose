# Proving it works

"It works" is three separable claims. Each is proved differently, and conflating
them is why agent-governance demos ring hollow. Everything here is reproducible:

```bash
make prove      # L1 + L2 + L3, regenerates the numbers below
make test       # 33 unit + benchmark tests
```

The rules under test are not invented for the benchmark — they are the
behavioral rules **lifted out of five real skills** in [`skills/`](../skills).
An agent following `skills/bug-fix/SKILL.md` emits the events the `tdd` module
judges, and so on. The skill says *what*; the lifted module says *how*.

| Skill | Lifted rule → module | Check tier |
|-------|----------------------|-----------|
| `bug-fix` | test-first → `tdd` | deterministic |
| `data-query` | mask PII → `pii-guard` | static (critical) |
| `commit-changes` | message format → `conventional-commits` | static |
| `write-file` | no secrets → `no-secrets` | static (critical) |
| `write-docs` | clear, hype-free → `prose-style` | LLM judge |

---

## L1 — does the layer *measure* correctly?

`benchmark/l1_conformance.py` scores every module as a violation classifier over
a **38-trace labeled corpus that includes adversarial near-misses** (mask one PII
column but leak another; an almost-conventional commit; a secret-shaped string
that isn't one).

```
                       P     R    F1   acc
conventional-commits  1.00 1.00 1.00 1.00
no-secrets            1.00 1.00 1.00 1.00
pii-guard             1.00 1.00 1.00 1.00
prose-style           1.00 1.00 1.00 1.00
tdd                   1.00 1.00 1.00 1.00
OVERALL               1.00 1.00 1.00 1.00   (TP20 FP0 FN0 TN18)
```

**This benchmark earned its keep on the first run.** It exposed two real bugs in
`pii-guard` — a proximity-based masking check that (a) missed a leaked `ssn`
sitting next to a masked `email`, and (b) false-flagged the table name
`email_events`. Both are now fixed (whole-word columns, per-column masking) and
pinned as regression tests (`test_pii_guard_regression_ssn_leak_and_table_name`).
That is the loop the whole project is about: a module is a unit, so its bugs are
findable and its fix is verifiable.

**Honesty about the tiers.** The deterministic/static modules *are* conformance
checks by construction, so L1 tests whether each **checker implements its spec**
(the adversarial rows are where implementation bugs surface) — not a model.
`prose-style` ships a deterministic *proxy* judge, so its L1 score measures
proxy-vs-spec consistency; measuring the judge's agreement with **human** labels
is the separate next step, and `benchmark/agent_sim.LabeledRun` is the interface
for it. Full report: [`benchmark/reports/L1_conformance.md`](../benchmark/reports/L1_conformance.md).

## L2 — does *enforcing* it improve outcomes?

`benchmark/l2_ablation.py` runs an 8-task suite twice with the **same seeded
agent decisions** — once with the harness off, once gating (reject a FAIL, retry
compliantly) — over 30 seeds. Because the agent's choices are identical in both
arms, the delta is the harness and nothing else.

| Metric | Harness off | Harness gating |
|---|---|---|
| Residual violation rate (final output) | **50%** | **0% ± 0%** |
| Task-success rate | 100% | 100% |
| Retries (enforcement overhead) / session | 0 | 4.0 ± 1.4 |

Gating removes **every** violation from the final output **without lowering task
success**, at a measured price of ~4 retries/session. And the ablation *measures*
the friction the cards claim: 15 of the retries came from forcing test-first on
**prototype** tasks — the quantitative basis for "know when *not* to use `tdd`."
Full report: [`benchmark/reports/L2_ablation.md`](../benchmark/reports/L2_ablation.md).

## L3 — does it plug onto a *real* agent?

`integrations/claude_code_hook.py` is a Claude Code `PostToolUse` hook. Real tool
calls become events, modules verdict them live, and the session accumulates into
a dashboard. Verify the whole pipeline without Claude Code:

```bash
python3 integrations/claude_code_hook.py --selftest
# [openharness] file.written  → no-secrets ✗ fail (critical) — forbidden content: aws access key
# [openharness] query.executed → pii-guard ✗ fail (critical) — unmasked PII in query: email
# selftest OK ✓
```

Wiring, the tool→event mapping, and the "never blocks the agent" guarantee are in
[`integrations/README.md`](../integrations/README.md).

## How to present the proof

- **The dashboard** (`make demo` → `dashboard.html`) as the headline artifact.
- **The two report tables** above — anecdote-free numbers, regenerated by `make prove`.
- **The bug it caught** — L1 finding and fixing the `pii-guard` leak is the single
  most convincing thing here: it shows the harness is genuinely testable, not
  decorative.
- **A 60-second screencast** of the L3 hook verdicts streaming during a live edit.
